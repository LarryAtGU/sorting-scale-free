# Deterministic Input Generation and Validation

## Fixed input sizes and trial identifiers

The production input sizes are

`N = {128, 256, 512, 1024, 2048, 4096}`.

For every `n` in `N`, generate exactly 1,000 permutations. Trial identifiers are
the integers

`seed = 1, 2, ..., 1000`.

The generated permutation must be a deterministic function of `(n, seed)`:

`permutation = generate_permutation(n, seed)`.

Every sorting algorithm receives a copy of the same permutation for the same
`(n, seed)` pair. Algorithms must not mutate the stored canonical input.

## Reproducibility requirement

Generation must be stable across processes, machines, and supported Python
versions. It must not rely on Python's randomized object hash or an unspecified
global random state.

The implementation will use a project-owned, explicitly specified pseudorandom
number generator and an unbiased Fisher-Yates shuffle. The generator algorithm,
integer sampling method, and format version will be recorded with the data. This
allows `(n, seed)` to reproduce the same permutation even if a third-party
library later changes its random-number implementation.

The seed material must include both `n` and `seed`; input size must not merely
change how many values are consumed from a shared stream.

## Validation of every generated sequence

For each `(n, seed)`, verify that:

1. the length is exactly `n`;
2. every value is an integer in `[0, n - 1]`;
3. every value occurs exactly once;
4. regenerating `(n, seed)` returns the identical sequence;
5. its checksum matches the saved manifest when a manifest exists.

Failure of any check invalidates the generated dataset.

## Duplicate-sequence validation

For a fixed `n`, no two seeds may generate the same permutation. The validator
will calculate a cryptographic digest of the canonical binary representation of
each permutation. If two digests match, it will compare the full permutations to
distinguish a true duplicate from a digest collision.

The validator reports duplicate groups and fails the dataset if any true
duplicate is present.

Duplicate checking is performed separately for each input size. Permutations of
different lengths are not comparable as duplicates.

## Ensemble randomness diagnostics

A single permutation cannot meaningfully "pass a randomness test." Randomness
diagnostics are therefore applied to the ensemble of 1,000 permutations for
each `n`.

The validation report will include at least:

1. **Position-frequency test:** for selected or grouped values, check whether
   positions are approximately uniform. Use a chi-square statistic with bins
   chosen to keep expected counts sufficiently large.
2. **Inversion-count test:** compare the sample mean and variance with the exact
   uniform-permutation values

   `E[I] = n(n - 1) / 4`

   and

   `Var(I) = n(n - 1)(2n + 5) / 72`.
3. **Fixed-point test:** compare the number of fixed points with its expected
   mean and variance, both equal to 1 for a uniform random permutation.
4. **Descent-count test:** compare the sample mean and variance with

   `E[D] = (n - 1) / 2`

   and

   `Var(D) = (n + 1) / 12`.
5. **Rank-correlation diagnostics:** inspect correlations between original and
   permuted positions and correlations across independently seeded trials.
6. **Reproducible diagnostic report:** save statistics, confidence intervals,
   adjusted p-values, warnings, generator version, and dataset checksum.

These tests are diagnostics against implementation errors and conspicuous bias;
they do not prove that a deterministic pseudorandom generator is truly random.
Because many tests are performed, the report will use a multiple-testing
correction and will not reject a complete dataset merely because one unadjusted
p-value falls below 0.05. A deterministic collection generated by a sound method
can occasionally produce an extreme statistic.

## Dataset acceptance

Acceptance has two levels:

- **Hard checks:** permutation validity, exact reproducibility, and absence of
  duplicate sequences. Every hard check must pass.
- **Statistical diagnostics:** the ensemble tests must show no systematic or
  severe departure from uniform-permutation expectations. The complete report
  is retained rather than reducing all evidence to a single pass/fail p-value.
